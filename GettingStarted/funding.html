    Funding Accounts¶

    A Superluminal account is identified by a Fogo Ed25519 wallet. Collateral is credited to a numbered trading subaccount after an EVM deposit is observed and settled on Fogo.

    The Fogo wallet and the EVM wallet have different roles:

    • The Fogo wallet authenticates the Superluminal account and selects the trading subaccount.
    • The EVM wallet sends collateral and pays EVM gas for manual deposits. It does not need to have the same address or private key as the Fogo wallet.

    Never send collateral until Superluminal has confirmed that the derived deposit address is registered.

    Keypair format¶

    The utilities accept a Solana-format Ed25519 keypair JSON file: a JSON array of 64 byte values. This is also the format produced by solana-keygen.

    Protect the file as a private key. The utilities load it locally and use it only to sign the WebSocket authentication challenge; the private key is never sent to Superluminal.

    Install the funding utilities¶

    The C++ and Python client bundles include cross-platform source utilities under funding-tools. They run with Bun on Linux, macOS, and Windows; no prebuilt executable is distributed.

    Requirements:

    • a supplied C++ or Python client bundle;
    • Bun 1.3.14 or newer; and
    • an existing Fogo keypair JSON file.

    Install runtime dependencies once from the bundle's funding-tools directory:

    cd funding-tools
bun install --production --frozen-lockfile

    Fund with the public testnet faucet¶

    From the bundle's funding-tools directory:

    bun run fund:testnet --keypair /path/to/wallet.json

    The command:

    1. authenticates the Fogo wallet through wss://testnet.slx.fi/ws;
    2. subscribes to trading subaccount 0;
    3. sends user_deposit_address and waits for UserDepositAddressStatus;
    4. derives the Arbitrum Sepolia deposit address;
    5. requests testnet USDC from the public faucet; and
    6. waits for UserCollateralUpdate to confirm that the trading balance increased.

    Successful output has this form:

    Fogo account:        <base58 wallet address>
Subaccount:          0
EVM deposit address: <0x deposit address>
Faucet transaction:  <0x transaction hash>
Trading balance:     10,000 USDC
Funding complete.

    Funding complete. confirms settlement into the trading account, not merely submission of an EVM transaction.

    The faucet funds subaccount 0 only. It currently mints 10,000 testnet USDC when settled collateral plus pending EVM deposits is below 1,000 USDC. An already-funded account normally receives HTTP 403 until its balance is below that threshold.

    Run the utility before starting the C++ or Python client for the same wallet. The funding session would otherwise preempt the client's authenticated session. The utility closes its own session before exiting.

    Run bun run fund:testnet --help for endpoint and timeout overrides.

    Derive an address for a manual deposit¶

    Use deposit:address for production or any manual ERC20 deposit. This command registers the Fogo wallet and subaccount, derives the corresponding EVM destination, and prints the authoritative EVM network and collateral token. It does not request an EVM private key or transfer funds.

    bun run deposit:address \
  --keypair /path/to/fogo-wallet.json \
  --gateway https://gateway.example \
  --evm-rpc https://evm-rpc.example \
  --partition-id <u16> \
  --subaccount <u64>

    Use the gateway origin, EVM RPC, and partition ID supplied for the same deployment. Successful output has this form:

    Fogo account:        <base58 wallet address>
Subaccount:          <subaccount id>
EVM chain ID:        <decimal chain id>
Collateral token:    <0x ERC20 address>
EVM deposit address: <0x deposit address>
Deposit address ready.
Transfer only the listed collateral token on the listed EVM chain.

    After Deposit address ready.:

    1. Configure the EVM wallet for the printed chain.
    2. Connect a trading client with the same Fogo wallet and subaccount.
    3. Transfer only the printed collateral token to the printed deposit address.
    4. Observe its account stream and wait for UserCollateralUpdate before treating the trading account as funded.

    The address utility exits after registration; it does not need to remain open while the EVM transfer settles.

    An EVM receipt proves that the transfer was submitted; it does not prove that the trading balance was credited. Sending on another chain or sending another token will not fund the account.

    How the deposit address is derived¶

    The deposit address is deterministic for a Fogo wallet and subaccount:

    salt = keccak256(fogo_wallet_bytes || uint64_be(subaccount_id))

deposit_address = last20bytes(
  keccak256(0xff || evm_vault || salt || user_deposit_init_code_hash)
)

    Inputs:

    • fogo_wallet_bytes: the authenticated 32-byte Ed25519 public key;
    • subaccount_id: the unsigned 64-bit subaccount number, encoded big-endian;
    • evm_vault: the gateway field from GET /v1/evm/addresses; and
    • user_deposit_init_code_hash: the matching field from that response.

    Fetch those values from the same HTTP origin used for the WebSocket connection. Do not hardcode deployment addresses.

    Before transferring collateral, authenticate the Fogo wallet and send:

    {
  "type": "user_deposit_address",
  "subaccount_id": 0
}

    Wait for the matching UserDepositAddressStatus. Registration success does not emit a generic ack accepted; validation or forwarding failures emit ack rejected or ack busy.

    See user_deposit_address for the full wire contract.

    Faucet errors¶

    • 400: malformed request, or the deposit address does not belong to the supplied wallet.
    • 403: settled collateral plus pending deposits is at least 1,000 USDC.
    • 502: an EVM or Fogo RPC operation failed.

    The public faucet does not require an EVM wallet or EVM gas.
